# 视觉与视频规格

## 一、铁律：AI 不写字

**AI 图像/视频生成模型画中文必错。** 不是「可能有点糊」，是笔画错乱、缺字、造字。

所以本 skill 走双轨：

| 轨道 | 谁来做 | 积分 | 负责什么 |
|---|---|---|---|
| A · 本地渲染 | 无头浏览器（HTML → PNG） | **0** | 所有带文字的东西：标题、卖点、价格、CTA、封面 |
| B · AI 生成 | ImageGen / VideoGen | 消耗积分 | **只做没有文字的氛围视觉**：背景、光效、动态 |

提示词里永远带上 `no text, no letters, no words, no watermark, no logo`。

**违反这条铁律的后果**：做出一张标题写错字的封面，发出去就是永久笑柄，
而且平台可能判「图片含违规文字」。宁可不做，也不要让 AI 写字。

## 二、宣传图规格

本地渲染的 4 张，尺寸是**精确出图**（不是近似），可直接上传：

| 图 | 尺寸 | 比例 | 用在哪 |
|---|---|---|---|
| 小红书封面 | 1242×1656 | 3:4 | 小红书首图；B站动态 |
| 电商主图 | 1080×1080 | 1:1 | 淘宝/拼多多主图（白底，平台有抠图要求） |
| 竖屏故事 | 1080×1920 | 9:16 | 抖音/视频号封面、朋友圈、状态 |
| 视频封面 | 1920×1080 | 16:9 | B站封面、落地页头图、视频首帧 |

补充平台要求：

- **电商主图必须白底**，留白充足，不要边框和阴影 —— 模板已按此固定为白底深字，
  不受项目主题色影响。主图第 1 张只放产品名 + 一行短副标，其余信息放第 2 张起。
- 缩略图尺寸下超过 12 个字基本读不清。**封面文字越少越好。**
- 截图一律 `object-fit: contain`，不要 `cover` —— cover 会把实机界面左右裁掉，
  连界面上的文字都切一半，这是硬伤。

## 三、ImageGen 调用规范

```
prompt:      英文描述 + 结尾固定加 "no text, no letters, no words, no watermark, no logo"
size:        横版 1536x1024 / 竖版 1024x1536 / 方版 1024x1024
quality:     high（主视觉值得）／ low（只做底纹时省钱）
output_dir:  <项目>/06-宣传图/ai
```

用途分两类：

1. **纯背景**（默认）：抽象氛围、光效、渐变。叠在本地海报底层或做落地页头图。
2. **图生图改风格**：传 `image1` = 实机截图，`input_fidelity: high`，
   提示词写「保持原布局可辨识，把它变成宣传级主视觉」。这样出来的图**还是你的产品**，
   不会变成另一个东西 —— 这条比纯凭空生成有用得多。

**每条提示词都要写明「不要文字」**，否则模型很可能自己在画面上加一堆乱码标题。

## 四、VideoGen 调用规范

**能力边界（必须先跟用户讲清）：**

- 一次只出 **5 秒**成片。
- 本机**没有 ffmpeg**，无法自动拼接多镜头。所以做法是：生成 N 条 5 秒镜头 + 一张分镜表，
  交给用户在剪映里拼（`05-视频分镜.md` 里已写好步骤）。
- 生成要 1–3 分钟。

```
prompt:       英文，描述运动（slow push-in / gentle pan / fade to dark），
              同样结尾加 "no text, no letters, no words"
image:        ★ 用本地渲染好的海报 PNG 作首帧（图生视频模式）
resolution:   1080P
enable_audio: 一般 true（需要音效时）
```

**关键：一律走「图生视频」，不要走「文生视频」。**
以本地海报为首帧，画面里的中文是准的；纯文生视频就是让 AI 自由发挥写字，必错。

**注意**：传了 `image` 之后**不要再传 `aspect_ratio`** —— 图生视频的画幅由首帧决定，
传了会冲突。

## 五、积分告知纪律（硬要求）

调用 ImageGen / VideoGen 前**必须先报预算并得到用户同意**。参考口径：

| 素材 | 单件消耗 | 备注 |
|---|---|---|
| ImageGen 单张 | 约 5–10 积分 | |
| VideoGen 5 秒 | 约 50–100 积分 | 比图贵一个数量级 |

`05-素材清单.json` 里的 `totals` 已按数量算好区间，直接念给用户听即可。

**不要说「我给你生成几个素材」就直接调。** 一条 20 秒视频 = 4 条镜头 ≈ 200–400 积分，
不打招呼就花掉，用户会不高兴，而且这是不可逆的消耗。

推荐给用户的顺序：

1. 先用**零成本本地海报**投出去看数据（0 积分，中文准确）
2. 有反馈再花积分做 AI 版本（P1 最小试水 ≈ 55–110 积分）
3. 数据好才做完整视频

## 六、无头渲染的坑（都踩过，别重复）

| 现象 | 原因 | 做法 |
|---|---|---|
| 脚本没输出、直接 SIGTERM | Python stdout 被缓冲，进程被杀时缓冲区丢失 | **一律用 `python -u` 跑脚本** |
| 第二张图尺寸/内容不对 | 复用了上一次的 user-data-dir | 每张换一个干净的 `--user-data-dir`，串行渲染 |
| 出图比预期大一倍 | 系统 DPI 缩放 | 固定加 `--force-device-scale-factor=1` |
| 中文变方块 | 指定了不存在的字体 | 用系统字体：`Microsoft YaHei` / `PingFang SC`，不要用装饰字库 |
| 排版溢出、底部被切 | 写死了区块高度 | 高度全走 flex，截图区用 `flex:1;min-height:0` |
| 副标吊着半个字结尾 | 按字数估算换行必然猜错 | CSS `-webkit-line-clamp` 交给浏览器裁 |

浏览器探测顺序见 `scripts/render_assets.py` 的 `BROWSERS`。
找不到浏览器时脚本会提示降级方案（手动打开 HTML 整页截图），不要硬报错。
